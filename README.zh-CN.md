[`lunar-rs`](https://crates.io/crates/lunar-rs)（纯 Rust 实现的寿星天文历引擎）的命令行
包装器。它提供三个子命令——两个照着它们各自对标的 Unix 工具设计，另一个是那些工具没有
对应物的：

- **`lunar date`** —— 某一天的农历档案：公历 / 星期 / 农历 / 干支 / 生肖 / 节气 /
  法定 / 星座，两个历法都能查，输入照 `date(1)` 的语法（`-d`），另有一个 `-f` 格式
  引擎和一个 `-a` 黄历区块。
- **`lunar cal`** —— `cal(1)` 风格的月、年网格，叠上农历日、节气、节日与法定日历
  （放假 / 调休），可按公历月，也可加 `-L` 按农历月。
- **`lunar bazi`** —— 生辰八字：出生时刻的四柱，附十神、藏干、纳音、地势、五行、
  旬空、地支十神与命局。唯一保留时钟的子命令，因为时柱需要它。

每一个历法答案——公历↔农历换算、二十四节气、干支、节日表、黄历（宜忌 / 冲煞 /
神煞 / 星宿 / 纳音 / 方位）以及国务院节假日表——都委托给 `lunar-rs`。本仓库只负责
参数解析、输出整形和网格排版，从不自行实现历法运算。

```bash
cargo build --release
./target/release/lunar date
./target/release/lunar cal
```

## 安装

提供 Linux x86_64 与 aarch64 的二进制，在目标架构上用标准 glibc 工具链构建：

```bash
# x86_64
curl -LO https://github.com/YangtseSu/lunar/releases/download/v0.1.0/lunar-0.1.0-x86_64.tar.gz
tar -xzf lunar-0.1.0-x86_64.tar.gz && sudo install -m755 lunar-0.1.0-x86_64/lunar /usr/local/bin/

# aarch64
curl -LO https://github.com/YangtseSu/lunar/releases/download/v0.1.0/lunar-0.1.0-aarch64.tar.gz
tar -xzf lunar-0.1.0-aarch64.tar.gz && sudo install -m755 lunar-0.1.0-aarch64/lunar /usr/local/bin/
```

每个 release 都带一份 `SHA256SUMS`，安装前先校验：

```bash
curl -LO https://github.com/YangtseSu/lunar/releases/download/v0.1.0/SHA256SUMS
sha256sum -c SHA256SUMS
```

或从源码安装：

```bash
cargo install --git https://github.com/YangtseSu/lunar
```

## `lunar date`

```console
$ lunar date -d 2026-09-07
公历: 2026年9月7日 星期一
农历: 丙午年七月廿六
干支: 丙午 丁酉 甲申
生肖: 马
节气: 白露
星座: 处女
```

当天没有节气时省略 `节气` 行；`星座` 行排在最后、从不省略，它只是公历月与日的函数。
闰月会出现在月名里：

```console
$ lunar date -d 2020-05-23
公历: 2020年5月23日 星期六
农历: 庚子年闰四月初一
干支: 庚子 辛巳 丙寅
生肖: 鼠
星座: 双子
```

输入有两个通道，两者共用同一套语法：

| 输入 | 含义 |
|---|---|
| *(无)* | 本地时区的今天 |
| `年 月 日` | 三个位置整数 |
| 单个位置参数 | 一个 `date(1)` 风格的字符串 |
| `-d, --date <DATE>` | 同样的 `date(1)` 风格字符串 |
| `-l, --lunar` | 把位置参数 / `-d` 的日期读作**农历**而不是公历 |
| `-R, --leap` | 配合 `-l`，指定闰月（不带 `-l` 时拒绝） |
| `-f, --format <FORMAT>` | 展开自定义格式，取代默认档案 |
| `-a, --almanac` | 在档案之后追加黄历区块（与 `-f` 互斥） |
| `--help-format` | 打印令牌表 |

`-d` 恒为公历，位置参数随 `-l`。两者在别处毫无区别，所以 `-d` 接受的每个字符串
`-l` 也接受——同一个字符串只是换到另一个历法里解析：

```console
$ lunar date -l -d 2026-07-15      # 农历 2026 年七月十五
公历: 2026年8月27日 星期四
农历: 丙午年七月十五
干支: 丙午 丙申 癸酉
生肖: 马
星座: 处女

$ lunar date -d 2026-07-15         # 公历 2026 年 7 月 15 日
公历: 2026年7月15日 星期三
农历: 丙午年六月初二
干支: 丙午 乙未 庚寅
生肖: 马
星座: 巨蟹
```

`-R` 指定闰月，所以 庚子年闰四月初一 解析为 2020-05-23：

```console
$ lunar date -l -R -d 2020-04-01
公历: 2020年5月23日 星期六
农历: 庚子年闰四月初一
干支: 庚子 辛巳 丙寅
生肖: 鼠
星座: 双子
```

只有指名*日期*的形式才切换历法。`now`、`tomorrow`、`next friday`、`+3 days`
说的是"哪一天"，而不是用哪个历法写的日期，所以它们对参考日的解析与不带 `-l` 时完全
一样。时刻（`T15:30`）属于公历语法，在 `-l` 下**拒绝**而不是忽略，免得农历日期看起来
像是尊重了一个被丢掉的时刻。

`-d` 认识：

- 关键字——`now`、`today`、`tomorrow`、`yesterday`；
- epoch 秒——`@1758240000`、`@-1`（向零截断，与 `date -d @…` 相同）；
- ISO 8601——`2026-09-07`、`2026-9-7`、`2026-09-07T15:30`、`20260907T1530`、
  `2026-09-07T15:30:45+08:00`、`2026-09-07T15:30:45.5+08:00`、`2026-09-07Z`；
  月或日可以不补零，只有时区没有时刻表示该时区的午夜，小数秒被接受并截断——本工具
  不留时钟，所以 `…T15:30:45.5+08:00` 与 `…T15:30:45+08:00` 是同一天；
- 斜杠——`2026/09/07`、`2026/9/7`、`09/07/2026`（月/日/年）；
- 相对偏移——`+3 days`、`-2 weeks`、`2 days ago`、`1 fortnight`、
  `next month`、`last year`；
- 星期名——`monday`、`sat`、`next friday`、`last friday`，以及中文的 `星期六`、
  `周二`、`礼拜六`、`星期天` / `周天` / `礼拜天`（这是本工具的扩展，`date(1)`
  没有中文星期名，遇到会拒绝）；
- 一个裸时刻——`15:30`、`15:30 UTC`，作用于今天；时区可以跨过午夜改日，所以
  `23:30+0800` 不一定是今天。

数值时区偏移用 **POSIX** 正负号约定：`+0800` 是比 UTC 慢 8 小时。短于一天的偏移
**拒绝**而不是忽略——本工具只回答日期、不留时钟，`90 minutes ago` 无处可移。

在国务院立法的日子里，档案会多出一行 `法定`——节日名，以及这一天是放假、还是被调休
挪到周末的上班日：

```console
$ lunar date -d 2026-09-26
公历: 2026年9月26日 星期六
农历: 丙午年八月十六
干支: 丙午 丁酉 癸卯
生肖: 马
法定: 中秋节 放假
星座: 天秤

$ lunar date -d 2026-10-10
公历: 2026年10月10日 星期六
农历: 丙午年九月初一
干支: 丙午 戊戌 丁巳
生肖: 马
法定: 国庆节 调休上班
星座: 天秤
```

在被指名的历法里不存在的日期照实报错，并给出农历月份的真实长度：

```console
$ lunar date -l -d 2026-07-31
lunar: 农历 2026 年七月没有第 31 天 (该月只有 29 天)

$ lunar date -d 2023-02-30
lunar: 公历 2023-02-30 不存在
```

### 自定义格式

```console
$ lunar date -f '%G年%M%N，星期%A，%Q' -d 2026-09-07
丙午年七月廿六，星期一，白露

$ lunar date -f '%G年%M%N，星期%A\n干支日：%D' -d 2026-09-07
丙午年七月廿六，星期一
干支日：甲申

$ lunar date -f '周%A 农历%M%N（日序 %n），生肖%S，节气：%Q' -d 2026-09-07
周一 农历七月廿六（日序 26），生肖马，节气：白露

$ lunar date -f '星座%Z，%Q' -d 2026-09-07
星座处女，白露
```

| 令牌 | 含义 |
|---|---|
| `%Y` | 公历年 |
| `%m` | 公历月 |
| `%d` | 公历日 |
| `%A` | 星期几单字 (一~日) |
| `%G` | 农历年干支, 春节换年 (丙午) |
| `%M` | 农历月汉字 (正月 / 闰六月 / 腊月) |
| `%N` | 农历日汉字 (初一) |
| `%n` | 农历日数字 (23) |
| `%H` | 干支月, 节气当日换月 (丁酉) |
| `%D` | 干支日 (辛巳) |
| `%S` | 生肖 (马) |
| `%Q` | 节气 (当日无则空) |
| `%Z` | 星座 (处女) |
| `%%` | 字面 `%` |


`%G` 与 `%H` 是本工具有意分开的两套基准。`%G` 是农历年，以春节换年——与 `农历:`
行所指的同一年，也是 `cal -L` 给各月加标题用的年。`%H` 是干支月，以节气当日换月，
因为黄历的宜 / 忌正是以那个月柱为键的。因此 `干支:` 这一行印的是立春年（`%G`
**不是**它印的东西），好让那三个柱构成一条自洽的链；两套基准在春节与立春之间以及
每个节气当日都会分歧，这就是同一天的 `农历:` 行与 `干支:` 行可能指向不同年份的原因。

`%A` 只给出星期那个字，所以任何前缀都能用：`星期%A` = 星期一、`周%A` = 周一、
`礼拜%A` = 礼拜一。反斜杠转义下一个字符并原样输出：`\n` 换行、`\t` 制表符、
`\r` 回车、`\%` 字面 `%`（与 `%%` 相同）、`\\` 字面反斜杠。
`lunar date --help-format` 打印同一张表。

### 黄历区块

`-a` / `--almanac` 在档案之后追加当天的黄历——宜忌、冲煞、神煞、星宿、纳音、方位与
物候，全部来自引擎自己的表：

```console

公历: 2026年9月7日 星期一
农历: 丙午年七月廿六
干支: 丙午 丁酉 甲申
生肖: 马
节气: 白露
星座: 处女
宜: 嫁娶、出行、伐木、拆卸、修造、动土、移徙、安葬、破土、修坟、立碑
忌: 掘井、祈福、安床、开市、入宅、挂匾、开光
冲煞: (戊寅)虎 煞南
值神: 闭  十二神煞: 天牢(黑道)
吉神: 月空、王日、天马、五富、不将、圣心、除神、鸣吠  凶煞: 游祸、血支、五离、白虎
二十八宿: 毕(吉) 值月 禽乌 门西白虎
纳音: 泉中水  旬空: 午未  六曜: 友引  小六壬: 留连  九星: 一白水天枢  月相: 蛾眉残
彭祖百忌: 甲不开仓财物耗散 / 申不安床鬼祟入房
胎神: 占门炉 外西北  胎元: 离
方位: 喜神艮(东北)、阳贵坤(西南)、阴贵艮(东北)、福神坎(正北)、财神艮(东北)
物候: 鸿雁来 (白露 初候)
```

其中两组是季节性的，一年里只有一段时间存在——数九从冬至起 81 天，三伏从夏至起——
所以在它们不存在的日子里，对应的行与 `节气` 一样被**省略**。2026-07-25 在中伏：

```console
$ lunar date -a -d 2026-07-25
公历: 2026年7月25日 星期六
农历: 丙午年六月十二
干支: 丙午 乙未 庚子
生肖: 马
星座: 狮子
宜: 祭祀、祈福、解除、整手足甲、安床、沐浴、入殓、移柩、破土、启钻、安葬、谢土
忌: 嫁娶、斋醮、开市、出火、入宅、移徙、出行、作灶、安门、伐木
冲煞: (甲午)马 煞南
值神: 执  十二神煞: 天刑(黑道)
吉神: 月空、金堂、解神、鸣吠对  凶煞: 月害、大时、大败、咸池、小耗、五虚、九坎、九焦、归忌、天刑
二十八宿: 氐(凶) 值土 禽貉 门东青龙
纳音: 壁上土  旬空: 辰巳  六曜: 大安  小六壬: 小吉  九星: 九紫火隐元  月相: 宵
彭祖百忌: 庚不经络织机虚张 / 子不问卜自惹祸殃
胎神: 占碓磨 房内南  胎元: 兑
方位: 喜神乾(西北)、阳贵离(正南)、阴贵艮(东北)、福神坤(西南)、财神震(正东)
物候: 腐草为萤 (大暑 初候)
三伏: 中伏第1天
```

每一个字段都只是那一天的函数，从不是某个时刻的函数——依赖时刻的那几个
（`time_yi`、`time_chong`）被有意排除，因为本工具不留时钟。`-a` 与 `-f` 互斥：档案
与区块是同一个答案的两种形态，而 `-f` 已经是接管输出的那一个。

## `lunar cal`

不带参数时打印当前公历月，每格公历日期下面压着农历日、节气或节日：

```console
$ lunar cal 2026 9
2026年9月
一              二              三              四              五              六              日
                1               2               3               4               5               6
                二十            廿一            廿二            廿三            廿四            廿五
7               8               9               10              11              12              13
白露            廿七            廿八            教师节          八月            初二            初三
14              15              16              17              18              19              20
初四            初五            初六            初七            初八            全民国防教育日  初十
21              22              23              24              25              26              27
十一            十二            秋分            十四            中秋节          十六            十七
28              29              30
十八            十九            二十
```

格内内容遵循固定优先级——**节日 > 初一显示月份名 > 节气 > 农历日**——所以 9 月 11 日
显示 `八月` 而不是 `初一`，9 月 7 日被白露覆盖，9 月 25 日被中秋节覆盖。两个历法的
节日都算：10 月 1 日显示国庆节。

### 法定日历与参考日

`lunar cal` 标记中国的法定节假日，那是一张公布的表，不是节日。每个标记都是属性，
从不是一个字符：

| 标记 | 显示为 |
|---|---|
| 法定节假日 放假 | 红色 |
| 调休——国务院把某个周末定成上班日 | 高亮加粗 |
| 参考日——本地时区的今天 | 反色 |

标记可以叠加，谁也不压过谁：既是放假日又是参考日的一天同时是红色*和*反色
（`ESC[31;7m`），而今天的调休日是加粗、高亮加反色。标记从不写进格子里——放假日
仍然写着中秋节，调休上班日仍然写着九月，因为那正是这个日历要显示的事实：

```console
$ lunar cal 2026 10
2026年10月
一          二          三          四          五          六          日
                                    1           2           3           4
                                    国庆节      廿二        廿三        廿四
5           6           7           8           9           10          11
世界住房日  廿六        廿七        寒露        廿九        九月        初二
12          13          14          15          16          17          18
初三        初四        初五        初六        初七        初八        重阳节
19          20          21          22          23          24          25
初十        十一        十二        十三        霜降        十五        十六
26          27          28          29          30          31
十七        十八        十九        二十        廿一        万圣节前夜
```

在终端里，10 月 1–7 日是红色，而 10 月 10 日——一个被国务院变成上班日的星期六——
是加粗高亮。**管道或重定向输出的网格完全不带标记**，因为标记是属性；`--color=always`
强制输出转义序列（给 `less -R`、`grep --color` 用），`--no-color` 强制关掉。
`--no-holiday` 去掉标记里的法定那一半，保留参考日自己的。单独查询某一天时，
`lunar date` 用文字报告法定日历。

`-L` 切到农历月，每格以公历日期领起：

```console

十二    十三    十四    中元节  十六    十七    十八
8/31    9/1     9/2     9/3     9/4     9/5     9/6
十九    二十    廿一    廿二    廿三    廿四    廿五
9/7     9/8     9/9     9/10
白露    廿七    廿八    教师节
```

### 选项

| 选项 | 含义 |
|---|---|
| *(无)* | 当前公历月（`-L` 为当前农历月） |
| `年` | 整年：12 个网格，从 1 月开始（`-L` 为整个农历年） |
| `年 月` | 那一个月 |
| `-L`, `--lunar` | 显示农历月而不是公历月 |
| `-R`, `--leap` | 配合 `-L`，选择闰月（不带 `-L` 时拒绝） |
| `-s`, `--sunday` / `-m`, `--monday` | 每周首日（默认周一） |
| `-y`, `--year` | 整年：12 个公历月；`-L` 为整个农历年 |
| `-3`, `--three` | 指名的那个月及其前后各一月 |
| `-n N`, `--months N` | 从指名的月开始，接下来的 `N` 个月（`N` ≥ 1） |
| `--number` | 农历日用数字，不用初一/廿六 |
| `--no-month-name` | 绝不把初一换成月份名 |
| `--no-festival` | 绝不显示节日 |
| `--no-holiday` | 绝不标记法定日历（放假 / 调休） |
| `--color[=WHEN]` / `--no-color` | `auto`（仅当 stdout 是终端）/ `always` / `never`；`--no-color` 即 `--color=never`。两者互相覆盖，后写的那个说了算。取值需要 `=`，如 `--color=always` |

跨度旗标读起来和 `cal(1)` 一样，每个窗口都自由跨越年界：`-3` 居中（`cal 2026 12 -3`
打印 2026年11月、2026年12月 和 2027年1月），`-n N` 起于指名的那个月，`-y` 是该月
所属的年——`cal 2026 9 -y` 打印 2026 年的十二个月，而不是从 9 月起的十二个月。参数
没指名的那个月就是参考日所在的月，所以 `cal -3` 以今天居中，`cal 2026 -3` 以今年
今天的月居中。没有跨度旗标就是整年，一个旗标都没有就是当前月。农历视图沿着连续的
农历月份序列行走，所以窗口也能跨过农历新年：`cal -L 2026 12 -n 3` 打印丙午年 腊月、
丁未年 正月、丁未年 二月，每个网格按自己的干支年加标题。越过 1–9999 的窗口会
被报出来，绝不裁剪。

## `lunar bazi`

生辰八字——出生时刻的四柱，附十神、藏干、纳音、地势、五行、旬空、地支十神与命局。
它是唯一保留时钟的子命令，因为四柱之一是时柱，没有时柱的命盘不是命盘：

```console
$ lunar bazi 1990-06-15T10:30

农历: 庚午年五月廿三
八字: 庚午 / 壬午 / 辛亥 / 癸巳
十神: 劫财 / 伤官 / 日主 / 食神
藏干: 丁己 / 丁己 / 壬甲 / 丙庚戊
纳音: 路旁土 / 杨柳木 / 钗钏金 / 长流水
地势: 病 / 病 / 沐浴 / 死
五行: 金火 / 水火 / 金水 / 水火
旬空: 戌亥 / 申酉 / 寅卯 / 午未
地支十神: 七杀偏印 / 七杀偏印 / 伤官正财 / 正官劫财正印
```

五行 是干的五行加支的五行，每柱两个字——`庚` 属金、`午` 属火，所以年柱读作 `金火`，
那不是纳音的五行（`路旁土` 属土）。地支十神 是支里每一个藏干对应的十神，所以一格
是一个短语：`午` 藏丁与己，对辛日干来说是七杀与偏印。

命局 是传统命盘摆在四柱旁边而不是柱内的四个值，各带自己的纳音。其中两个按时辰
推算，所以它们和时柱一样需要时钟，也是没有时刻的出生时刻答不出的第二件事：

```console
$ lunar bazi 1990-06-15

农历: 庚午年五月廿三

说明: 未给时刻，无时柱

旬空: 戌亥 / 申酉 / 寅卯

说明: 未给性别，无大运
```

胎元 与 胎息 不需要时辰，保留；命宫 与 身宫 被略去并说明原因，而不是用工具不得不
凭空造出来的中午去填。凡是属于某根柱的行，在没有时柱时都裁成三格，所以没有哪一行
留着命盘已经不存在的第四格。

那些 `说明` 行是工具在讲输入答不了什么：先是时柱，然后是命宫 / 身宫，然后是大运。
每一样都报出来，而不是给个默认值。

日期由 `lunar date -d` 用的同一套语法解析，所以这里每种形式都接受——
`1990-06-15 10:30`、`19900615T1030`、`1990/06/15 10:30` 和
`1990-06-15T10:30+08:00` 是同一时刻。关键字（`yesterday`）与相对偏移
（`2 days ago`）指名的是一天而没有时刻，与 `date` 里完全一样。这里没有 `-l`：出生
时刻是一个公历时刻，没有"农历的时刻"可读。

**这里的月柱在节气*瞬间*换柱，而 `lunar date` 在节气*当日*换柱——两者都对，因为它们
回答的是不同的问题。** 2026 年白露落在 22:41:16，所以当天 20:00 的出生是申月，
23:00 的是酉月，而当天自己的黄历把 09-07 一整天都叫作酉月：

```console
地支十神: 伤官正财 / 七杀偏印偏财 / 七杀偏印偏财 / 偏财正官伤官
```

年柱与日柱是 `lunar date` 印的同样的事实、同一套基准，所以两个子命令绝不会在它们
上分歧——包括那个属于它开始那一天的子时，而不是它结束的那一天。

### 时柱与真太阳时

时柱由你输入的**钟表时**推算，本工具不把它校正成真太阳时——即太阳真正位于子午线
上的当地时刻。传统八字用的是后者，所以这里给出的命盘是钟表时命盘，应当照钟表时读。

差距是每偏离标准子午线一度的四分钟，加上当时若有夏令时的一小时，再加上时差方程
（−14 到 +16 分钟，单靠它不够）。对北京（东经 116.4°）大约是 14 分钟——通常不足以
挪动一根柱。对乌鲁木齐（东经 87.6°）大约是 128 分钟，**这足以**把时柱挪动一个
时辰，起运也跟着动。全国统一用东经 120° 的一个时区，所以出生地越偏西，差距越大。

夏令时是另一半：中国在 1986 到 1991 年实行过，而 1986-05-04 到 1986-09-14 之间
钟面快一小时，足以把临近 23:00 的出生挪到第二天。

这些一概不校正，而且它们都不是引擎的 bug——引擎只是给它拿到的那个时刻排盘。要
校正就得有出生地经度，而这个输入本工具从未接受过；各派对于是否要校正、该用三种
定义里的哪一种也没有共识。引擎本身没有真太阳时实现，所以这项校正得先在引擎里建起来。
在此之前，本段就是关于时柱的全部真相。

## 支持范围

年份 **1–9999**，即 `lunar-rs` 能服务的窗口：它的天文计算被 `LEAP_11` / `LEAP_12`
表限定，窗口之外外推的农历月与节气并不可靠。窗口外的年份、不存在的日期，以及格里
高利改历跳过的那十天（1582-10-05 … 1582-10-14）都报为错误，绝不渲染：

```console
$ lunar cal 10000
lunar: 年份 10000 超出支持范围 (1–9999)

$ lunar date -d 2023-02-30
lunar: 公历 2023-02-30 不存在
```

农历 9999 年腊月是最后一个农历年里唯一一个网格画不出的月：它起于 9999-12-30，
止于 10000-01-27，它的日子走出了范围。这个月按名字报出来，而不是被裁剪——被裁剪的
网格会与 `lunar date` 在同一天上给出不同答案。它周围的月份不受影响：
`cal -L 9999 11` 照样印 农历 己亥年 冬月。

```console
$ lunar cal -L 9999
lunar: 农历 9999 年腊月跨入 10000 年，超出支持范围 (1–9999)
```

法定日历是另一个数据窗口：`lunar-rs` 附带的是它拿到手的那些年份（本次发布为
2001–2026），所以窗口外的网格只有节日，没有放假 / 调休标记。这个窗口是公布表的
属性，不是本工具能算出来的东西。

## 已知差异

与对标工具的行为差异是缺陷而不是特性，并以实施计划的形式跟踪在
[`docs/plans`](docs/plans)。[`docs/parity.md`](docs/parity.md) 里的兼容矩阵列出
`date(1)` / `cal(1)` 接受的每一种形式、哪些还开着、哪些是有意保留的以及各自的理由。

| `src/calendar.rs` | `lunar-rs` 的边界：范围检查、公历↔农历换算、干支、节日、节气、星座、黄历区块、法定节假日 |
| `src/civil.rs` | 前推格里高利历的历元运算与日期步进，`lunar-rs` 给不了，因为它的 `Solar` 建模了 1582 改历 |
| `src/calgrid.rs` | 网格排版；格子按**显示宽度**（`src/lang.rs`）而非字符数补白，所以 CJK 格子对齐 |
| `src/cell.rs` | 格内内容优先级（节日 > 初一显示月份名 > 节气 > 农历日） |
| `src/mark.rs` | 参考日 / 放假 / 调休 标记，唯一写 SGR 的地方 |
| `src/datestr.rs` | `date(1)` 风格的 `-d` 语法 |
| `src/format.rs` | `-f` 令牌引擎 |
| `src/tz.rs` | 从 `TZ` / 系统时区取本地"今天" |
| `src/commands/` | 三个子命令的界面 |

子命令模块从不打印：它们往 `main` 一次性写到 stdout 的那个 `String` 上追加，所以任何
一处失败都不输出内容并以非零码退出。


`tests/documented_examples.rs` 启动真实二进制，钉住文档里的排版、令牌表、跨度与叠加
开关，以及错误消息，另按日期钉住历法值。已公布的样例与天文引擎冲突时，以引擎为准。

## 开发方式

本项目在 AI 编码智能体辅助下开发：由人提出需求、审阅每一处改动，并把每条结论都拿到
工具的真实运行上核对；代码主要由 AI 生成。本仓库不含任何自行实现的历法运算——那属于
`lunar-rs`，两者的分工写在 `AGENTS.md` 里。

两件事让这件事站得住：README 里的每条样例都从真实运行抄来，并在每次 push 时逐字节校验；
而 `AGENTS.md` 整个是一组契约——干支基准、闰月的负号、`干支` 行用立春年——写在明处，
后来的改动要推翻它们就必须先说明理由，而不是悄悄地破坏。

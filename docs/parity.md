# 与 cal(1) / date(1) 的兼容矩阵

判定基准：本机 GNU coreutils 9.11 的 `date`，util-linux 2.42.3 的 `cal`。
矩阵中每行都经真实执行验证（2026-09-26，时区 Asia/Shanghai）。

记号：✅ 一致 · 🚧 是缺陷，已立案（计划号）· 🔒 有意保留，理由见文末。

## `lunar date`（对照 `date(1)`）

| `-d` 输入 | 本机 `date` | `lunar date` | 判定 |
|---|---|---|---|
| `2026-09-07` | 2026-09-07 | 2026-09-07 | ✅ |
| `2026-9-7`（不补零） | 2026-09-07 | 2026-09-07 | ✅ |
| `2026-09-07T15:30` | ✅ | ✅ | ✅ |
| `2026-09-07T15:30:45+08:00` | ✅ | ✅ | ✅ |
| `2026-09-07T15:30:45.123456789+08:00` | ✅ | ✅ | ✅（小数截断） |
| `2026-09-07Z` | ✅ | ✅ | ✅ |
| `20260907T1530` | 2026-09-08 | 2026-09-07 | 🔒（我们按 `hhmm` 读，见文末） |
| `2026-09-07 15:30` | ✅ | ✅ | ✅ |
| `@1788000000` | ✅ | ✅ | ✅ |
| `@-1` | 1970-01-01 | 1970-01-01 | ✅（向零截断） |
| `1758240000`（漏 `@`） | `invalid date` | `无法解析的日期` | ✅（同为拒绝，措辞不同） |
| `2147483647 days` | `invalid date` | `年份 5881637 超出支持范围` | ✅（合法相对表达式，结果越界） |
| `2147483600 years` | `invalid date` | `年份 2147485626 超出支持范围` | ✅（真算出的年份，而非回绕值） |
| `90 minutes ago` | 今天 | `日期偏移单位 … 不足一天` | 🔒（无时钟） |
| `9 hours ago` | 今天 | 同上 | 🔒 |
| `2 days` / `1 month ago` / `next month` / `last year` | ✅ | ✅ | ✅ |
| `monday` / `sat` / `next friday` / `last friday` | ✅ | ✅ | ✅ |
| `周六` / `星期二` / `礼拜六` / `星期天` | `invalid date` | 同解 `saturday` / `tuesday` | 🔒（本工具的扩展，见文末） |
| `15:30` | 今天 | 今天 | ✅（时钟被有意丢弃） |
| `15:30 UTC` | 今天 | 今天 | ✅（带时区，跨零点则改日） |
| `TZ="UTC" 2026-09-07` | ✅ | `无法解析的日期` | 🔒（前缀式 TZ 不做） |
| `next friday -3 days` | ✅ | `无法解析的日期` | 🔒（组合相对表达式不做） |
| `10000-01-01` | `invalid date` | `无法解析的日期` | ✅（引擎范围 1–9999） |
| 无参数 | 当前时刻 | 今天的农历档案 | 🔒（输出形态是产品定义） |
| `date -u` / `-r` / `-s` / `-R` / `+FORMAT` | ✅ | 不提供 | 🔒（本工具 `-R` 是闰月、`-f` 是自有令牌） |

`-d` 与 `-l` 的分工是产品定义：`-d` 恒为公历，位置参数随 `-l`；两者走同一语法
通道（`datestr`），所以 `date -l -d 2026-07-15` 与 `date -l 2026 7 15` 必然同解。

## `lunar cal`（对照 `cal(1)`）

| 旗标 / 形态 | `cal(1)` | `lunar cal` | 判定 |
|---|---|---|---|
| 无参数 | 当月 | 当月（公历/`-L` 为农历月） | ✅ |
| `年`（如 `cal 2026`） | 整年 | 整年（12 个月，1 月起） | ✅ |
| `年` 配跨度旗标（`cal -3 2025`） | 用**今天的月**补齐 | 同左 | ✅ |
| `月 年`（如 `cal 9 2026`） | 2026 年 9 月 | `月份 2026 非法` | 🔒（我们保持 `年 [月]`，见文末） |
| `日 月 年` | 支持 | `位置参数过多` | 🔒 |
| 月名（`cal September 2026`） | 支持 | 不支持 | 🔒 |
| `-3` | 指定月**前后三个月**（跨年） | 同左（公历与农历都居中，农历可跨农历年） | ✅ |
| `-n N` | **从指定月起** N 个月（跨年） | 同左 | ✅ |
| `-y` | 指定日所在的**整年**（1–12 月） | 同左（`-L` 为该农历年全部月份，含闰月） | ✅ |
| `-s` / `-m` | 周日起 / 周一起 | 同左（默认周一） | ✅ |
| `--color[=WHEN]` | `auto/always/never`，与 `--no-color` 互相覆盖（后写者胜） | 同左 | ✅ |
| `-1` | 单月 | 默认行为 | ✅ |
| `-j` / `-w` / `-v` / `-c` / `--reform` 等 | 支持 | 不提供 | 🔒（界面扩展见文末） |
| `-L` / `-R` / `--number` / `--no-*` | 无 | 扩展旗标 | 🔒（本工具的农历能力） |
| 多月排版 | 并排 3 列 | 纵向堆叠 | 🔒 |
| 法定节假日 / 今天 | 仅今天高亮（部分地区） | 放假红 / 调休亮黄 / 今天反色，属性叠加 | 🔒（产品定义） |

## 有意保留（🔒）及其理由

- **`date` 与 `cal` 无时钟。** 这两个子命令只回答"哪一天"，因此不做 `date` 的
  设置时间、`-u`、`-r`、输出时刻；不足一天的相对偏移**拒绝**而不是静默忽略，
  因为那会是假装已生效。`lunar bazi` 是唯一读时刻的地方，因为它有时柱——
  没有时刻的八字只有三柱，该子命令照实印三柱而不补一个。
- **`-R` 是闰月，不是 RFC 2822。** 与 `date(1)` 的同名旗标无关；本工具没有
  RFC 输出，改名会破坏既有文档与测试，保留并在 README 说明。
- **`cal` 位置参数保持 `年 [月]`。** `cal(1)` 的 `[日] 月 年` 与 `lunar date`
  的 `年 月 日` 相反，且有歧义（`cal 9 12` 无法从两个数字判断谁是哪年）。本工具
  选择无歧义的顺序，代价是与 `cal(1)` 不同；已登记的差异，不再视为缺陷。
- **`TZ="…"` 前缀、组合相对表达式**（如 `next friday -3 days`）不做：前者与
  进程级 `TZ` 环境变量重复，后者需要完整表达式求值器，收益不成比例。
- **`20260907T1530` 按 `hhmm` 读。** `date(1)` 对同一串给出次日，属其自身怪癖；
  我们的读法与本工具文档一致，保留。
- **中文星期名是本工具的扩展。** `星期X` / `周X` / `礼拜X`（X ∈ 一…日，另收
  `天`）与 `monday` 同解，`next 星期六` / `last 周天` 随之可用；`date(1)` 没有
  中文星期名，一律 `invalid date`。本工具本就用中文输出，`%A` 之外再接受中文
  星期名是同一取舍，登记为有意扩展而非缺陷。
- **多月排版纵向堆叠、法定节假日着色**：网格要容纳农历内容，并排三列不可读；
  着色不进文本是 `mark.rs` 的核心取舍（见 AGENTS.md）。
- **扩展旗标**（`-L`、`-R`、`--number`、`--no-month-name`、`--no-festival`、
  `--no-holiday`）是农历能力的一部分，不是 `cal(1)` 的替代。

- **干支月取节气当日基准，干支年取立春基准。** 对 `date(1)` / `cal(1)` 无对应
  （二者都不印干支），故不构成兼容性差异；登记在此是因为它是本工具的既定选择，
  且**必须在两处一致**：`干支:` 行的月柱必须是黄历 `宜` / `忌` 查表所依据的那一个
  （`Lunar::day_yi` / `day_ji` 用 `month_in_gan_zhi()`，即节气**当日**换月，而非
  引擎另一个 `month_in_gan_zhi_exact()` 的节气**瞬时**换月；两者在每年 12 个节气
  当日不同，1–9999 共 119,988 天）。同一条理由要求 `干支:` 行的年柱用立春基准，
  因为月干由五虎遁自立春年干推出，混用春节年干会印出五虎遁不成立的柱对（1–9999
  共 74,948 天）。`农历:` 行、`%G`、`%S` 与 `cal -L` 标题仍用春节基准——它们说的是
  农历年本身，不是干支链。

## `lunar bazi`（无对应工具）

`date(1)` / `cal(1)` 都不排八字，本子命令没有可比对象，故不进入上面的兼容矩阵。
它自身的两处取舍登记在此：

- **无时刻则三柱，不补时柱。** 给了日期没给时刻时，输出三柱并印一行
  `说明: 未给时刻，无时柱`；不从当前时钟、也不从出生地推定一个时刻——那会造出
  用户没写的事实。`date` 对时刻一向丢弃，这里是同一取向的另一种表现：一个没有
  时柱的八字仍然是三柱，只是它只有三柱。
- **月柱取节气瞬时基准，与 `date` 的干支行不同。** `date` 印的是**一天**的干支，
  月柱在节气当日即换；八字排的是**一个出生时刻**，白露 22:41 之前出生属申月、
  之后属酉月，这正是引擎 `EightChar` 的口径。两者在每个节气当日不同（1–9999 共
  119,988 天），其余全同，年柱与日柱则始终同源。**两者都对，不要互相"修正"**。
- **不做大运。** 大运需要性别，且起运的月数算法各家不同，属另一问题。

## 新增差异的处理流程

任何新发现的差异先登记到本文件，并判为以下三者之一：

1. **缺陷** —— 立案到 `docs/plans/NN-*.md`，进入队列；
2. **有意保留** —— 在本文写下理由与影响；
3. **上游问题** —— 记录到 AGENTS.md 的 Dependency First（引擎负责，本仓库不改）。

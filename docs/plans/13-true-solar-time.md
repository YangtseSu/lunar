# 计划 13 — 真太阳时：只做方法论声明，不实现

Status: 已实施（2026-09-28） · Priority: P2 · Depends: 09

## 现象

`lunar bazi` 按**钟表时**排时柱。而传统八字用的是**真太阳时**——太阳实际到达
 meridian 的时刻。两者在高经度地区、夏令时地区、以及「地方平太阳时」口径下可
差一个时辰（两小时），直接改变**时柱**，而时柱是八字的一部分。

本工具目前**对此一言不发**，用户会默认自己拿到的是真太阳时。这不是引擎缺陷：
`lunar-rs` 全库无 `真太阳` / `longitude` / `true_solar` 任何实现（已 grep 确认），
它按传入的钟表时排盘，这是合理的——校正真太阳时需要经度输入，而经度不是日历。

```console
$ lunar bazi 1990-06-15T10:30
公历: 1990年6月15日 10:30        <- 钟表时，未作真太阳时校正
…
八字: 庚午 / 壬午 / 辛亥 / 癸巳
```

## 归属

**方法论声明，不是缺陷。** 引擎按钟表时排盘是对的；本工具缺的只是把这件事说出来。
**上游问题**部分：无——若日后要真太阳时，应先在 `lunar-rs` 实现，本仓库再暴露。

## 目标行为

**只改文档，一行代码不动。** 三处声明：

1. **README 八字节**加一段：说明时柱按钟表时；给出影响量级与例；指向本计划。
2. **AGENTS.md「Command Surface Contracts」**加一条契约：不得声称或暗示本工具
   输出真太阳时八字；若将来实现，须先在引擎。
3. **`docs/parity.md` 八字专节**登记为有意保留，理由是缺经度输入。

### 声明必须写清的四点

- **本工具的时柱 = 钟表时的时柱**，未经真太阳时校正。
- **差异可达一个时辰**：北京（东经 116.4°）比东经 120°标准时慢约 14 分钟，一般
  不够移柱；但乌鲁木齐（东经 87.6°）慢约 128 分钟——**足够把时柱移一位**。
  中国全境用东八区单一时区，西部偏差最大。
- **夏令时**是另一条：1986–1991 年中国行夏令时，1986 年 5 月 4 日至 9 月 14 日
  出生者，钟表时比标准时快 1 小时，恰在 23:00 前的临界生辰会换日。
- **不做校正不是缺陷**：校正需要出生地经度，那是新输入；且各家对「是否校正、
  用哪个口径」本身有分歧。声明现状比假装已校正诚实。

## 实施步骤

1. `README.md` 八字节加「时柱与真太阳时」小节。
2. `AGENTS.md` 加契约一条。
3. `docs/parity.md` 登记。
4. 测试：加一个断言，锁定「README 的这个声明存在」，防被后续编辑删掉——
   **这是文档契约，不是日历行为**，用 `contains` 即可，不必新建测试文件。

## 取舍（登记于 `docs/parity.md`）

- **只声明，不实现。** 实现真太阳时要引入经度输入（本工具目前无「地点」概念），
  且要先在 `lunar-rs` 落地；两者都不是本仓库单方面能决定的。
- **不做「若接近时辰边界则提示」之类的启发式**：那会让用户以为工具知道出生地。

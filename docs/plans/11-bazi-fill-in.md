# 计划 11 — 八字补全：旬空、五行、胎元、命宫/身宫、地支十神

Status: 已实施（2026-09-28） · Priority: P2 · Depends: 09

## 现象

`lunar bazi` 目前印六行（四柱 / 十神 / 藏干 / 纳音 / 地势），而传统八字盘上
与四柱并列的四项——**胎元、命宫、身宫**——一项都没有；**旬空**与**五行**同样缺席。
引擎全部已实现（`EightChar` 64 个方法），本仓库未暴露。

```console
$ lunar bazi 1990-06-15T10:30 | tail -2
纳音: 路旁土 / 杨柳木 / 钗钏金 / 长流水
说明: 未给性别，无大运
```

## 归属

**本仓库未暴露的能力**（引擎已实现，无须上游改动）。本项无新口径、无新输入，
是纯粹的「把已有的印出来」。

## 目标行为

在 `地势` 之后追加三行四列的，再追加一个不按柱对齐的「命局」行：

```
五行: 金火 / 水火 / 金水 / 水火
旬空: 戌亥 / 申酉 / 寅卯 / 午未
地支十神: 七杀偏印 / 七杀偏印 / 伤官正财 / 正官劫财正印
命局: 胎元 癸酉(剑锋金) / 胎息 丙寅(炉中火) / 命宫 壬午(杨柳木) / 身宫 戊子(霹雳火)
```

1. **五行、旬空、地支十神**按四柱对齐，三/四列，规则同十神/藏干/纳音/地势。
2. **命局**四项是单一值，不按柱对齐，单独成行。
3. **命宫 / 身宫依赖时柱**，无时刻时**省略这两项**并说明——这是继时柱之后
   第二个「输入不足以回答」的情形，与既有两处取向一致。
4. 胎元 / 胎息 / 命宫 / 身宫 的干支由引擎给出，本仓库只排版，不重算。

## 取舍（登记于 `docs/parity.md`）

- **不印「空亡/空亡神」等别名**，只用引擎给的「旬空」名。

测试：

- `the_pillar_rows_all_align_to_the_pillars` —— 无时刻时五行/旬空/地支十神均为三列。
- `the_ming_gong_needs_a_time_pillar` —— 无时刻时命局只有胎元/胎息，且有一行说明。
- `the_five_elements_open_with_the_stems_own_element` —— `庚` 金、`午` 火
  ⇒ 年柱 `金火`；日柱 `辛` 金、`亥` 水 ⇒ `金水`。五行是引擎按干支逐字给的，
  该测试钉住它没被排版代码改动。

## 已核实（本文件写入时实测）

上表所有取值来自 `Lunar::eight_char` 直读，**已核实**；两处曾被猜错，记录在此
以免重犯：

- **五行是「干五行 + 支五行」两字**，不是纳音的五行。`庚`(金) + `午`(火) =
  `金火`，与纳音 `路旁土` 无关。
- **地支十神按地支藏干逐字列出**，`午` 藏丁己而日干为辛，故年柱地支十神是
  `七杀偏印`（丁对辛为七杀、己对辛为偏印），不是一个词。
- **命宫 / 身宫 依赖时柱**：以正午代入时引擎返回 `辛巳` / `己丑`，是**用正午
  算出来的值**，不是「无时柱」的正确回答，故无时刻时必须省略。

## 实施后记录（2026-09-28）

**步骤 0 与步骤 2 落在同一遍改动里**，没有"只搬移、零输出变化"的中间状态可测。
不丢行的证据是 pinned 测试：`bazi_prints_four_pillars_only_with_a_time` 失败时
打印的 `left`（真实输出）逐行仍是拆分前的七行、顺序未变，只在其后多了五行 /
旬空 / 地支十神 / 命局四行。套件 87 → 89。

实现与计划的两处差异：

- **列数由 `column_count` 一处决定**，不是每行各自 `truncate`。三柱模式下八字与
  七行四列属性（十神 / 藏干 / 纳音 / 地势 / 五行 / 旬空 / 地支十神）全部走
  `cells[..column_count]`，新增行不可能漏掉截断。
- **命局 四项拆成两个 helper 调用**：`write_ming_jun` 收 `has_time`，据此决定
  是四项还是两项，并印 `说明: 命宫 / 身宫需时柱`。「输入不足以回答」的说明行
  因此与该行同处一个函数，不会再次走失。

`命局` 一行实际输出与「验收」一节逐字节一致（含 `胎元 癸酉(剑锋金)` 的半角
括号与 ` / ` 分隔）。
